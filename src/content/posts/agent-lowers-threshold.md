<p>从中小企业 HR 手动核对学历说起，很多白领的重复活本可以交给脚本，却很少有人写。agent 把门槛降到了能把任务说清楚，可多数人还没意识到这些活能交出去。</p><p>在不少中小企业里，HR 每到招聘旺季，要核对一批候选人的学历。常见的做法是打开学信网，把候选人提供的信息一条条输进去，查到结果后截图，再回到表格里标上“已核实”。二十个人就要重复二十遍，中间输错一个字，又得重新查。</p><p><img src="/images/posts/agent-lowers-threshold/fig-01.webp" alt="HR 埋头逐条查询，旁边的 agent 没人用" srcset="/images/posts/agent-lowers-threshold/fig-01-800.webp 800w, /images/posts/agent-lowers-threshold/fig-01.webp 1280w" sizes="(max-width: 768px) 100vw, 760px" width="1280" height="720" loading="lazy" decoding="async"></p><p>这件事其实可以交给脚本：读取表格，逐条查询，把结果写回去。懂一点编程的人花一两个晚上大概就能写出来。大公司往往有现成的系统或外包的背调服务，中小企业通常两样都没有，可真自己动手写脚本的 HR 还是很少。</p><h2>这样的活，几乎每个白领手上都有</h2><p>HR 并不特殊。财务每到月底，要把银行流水和账上的记录逐笔对一遍，找出金额或日期对不上的几笔。销售运营每周要从几个后台导出数据，复制到同一张表里，再按区域汇总成周报。行政要把几十张报销单上的金额、日期和发票号录进系统，再和发票原件核对。</p><p>这些活的共同点是规则清楚、步骤固定、每次都差不多。按理说都适合写成脚本，可现实中多数人还是一遍遍手动做。</p><h2>少有人写脚本，是因为学的成本高过省下的时间</h2><p>原因并不复杂。写脚本要先学一门语言，还要弄懂文件格式、网页请求和出错后的排查。这些知识和财务、销售、行政的本职工作关系不大，学会它们花的时间，很可能比一年里手动处理花掉的时间还多。算下来不划算，大多数人就继续手动做了。</p><p>这样选择是合理的。工具一直都在，只是用上它的门槛太高，挡住了大部分人。</p><h2>有了 agent，门槛从“会写代码”变成了“能把活说清楚”</h2><p>现在情况有些不同。HR 可以对 agent 说：“这是候选人表格，帮我逐个核对学历，把结果填在最后一列，对不上的标出来。”财务也可以说：“把这个月的银行流水和账上的记录对一遍，列出对不上的几笔。”他们不需要知道脚本怎么写，只要能把要做的事讲清楚。</p><p>agent 也会出错，结果仍然需要人抽查和判断。但要跨过的门槛已经从“会编程”变成了“会描述任务”，而描述自己每天在做的事，大多数人都做得到。</p><h2>卡住大多数人的，可能是还没意识到这些活能交出去</h2><p>我觉得现在的瓶颈主要不在能力上。很多人已经习惯了这些事要自己动手，很少停下来想一想，它能不能描述出来，交给别人去做。日常的重复工作早已融进流程，不显眼，也不算麻烦，只是一遍遍地占掉时间，所以人们很难把它当成一项“任务”来看待。往往要等身边有同事先试过，说一句“我让 agent 把这周的对账做完了”，其他人才会回头想到自己手上也有类似的活。</p><p>以前想到了也没用，因为要先学会写脚本。现在能做到了，多数人却还没有把“交给 agent”列进自己的选项。这种认识上的滞后，可能比技术本身更能决定谁先用上 agent。技术换代时常常是这样：工具先到，大部分人的工作习惯要过一段时间才跟上。</p><p>上一篇《<a href="/posts/a2a-outcome-delivery/">给 agent 卖东西，现在有哪几种做法</a>》里提到的按次计费的核验服务，正是这类 agent 背后会调用的东西。这类服务能不能做大，可能要先看有多少白领意识到，手上那些核对、整理、搬运数据的活，可以交给 agent 去做。</p>
